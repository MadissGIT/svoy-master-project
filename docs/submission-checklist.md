# Проверка перед сдачей

## ДЗ 1 «Анкета»

Тема «Предпочтения в кино», индивидуальное задание.

- В `Homework/MovieSurvey/MainPage.xaml` есть все обязательные контролы и свойства из задания.
- Каждый UI-элемент, включая контейнеры и страницу, имеет уникальный `x:Name` вида `_Name_`.
- Grid задаёт строки и столбцы явно, дочерние элементы указывают оба индекса.
- Привязка Stepper использует `x:Reference`, `Path` и `Mode`.
- Для проверки в приложении: показать результат пустой анкеты, затем ввести имя и корректный возраст, выбрать ответы и показать сводку.
- Изменить ответ после показа: старая сводка должна скрыться. Нажать «Очистить»: поля и результат должны вернуться в исходное состояние.
- Проверить доступность нижних полей и кнопок на небольшом экране через прокрутку.

Автоматическая проверка имён, привязок и статусов заявок:

```sh
dotnet run --project Tests/ScenarioChecks/ScenarioChecks.csproj
```

## Проект «СвойМастер»

На защите нужны [презентация](project-passport.pptx), [прототип](../Prototype/index.html) и запущенное приложение. В проекте семь экранов, без учёта заставки.

1. Открыть поиск. Проверить фильтры и запрос, который не находит мастеров.
2. Выбрать любого мастера и создать заявку. Пустая форма и прошедшее время должны давать ошибку.
3. Вернуться к выбору роли. Открыть кабинет и выбрать того же мастера.
4. Принять заявку, затем отметить работу выполненной.
5. Вернуться в роль клиента и подтвердить выполнение. При включённом автоплатеже появляется только демонстрационная отметка об оплате.
6. Повторить для другого мастера. Доступность и демопроверка должны относиться только к выбранному мастеру.
7. Проверить отклонение и отмену: заявка остаётся без оплаты.
8. Перезапустить приложение: заявки и статусы должны сохраниться.

Проверка `Android build and launch` собирает оба приложения и запускает их в Android-эмуляторе. APK и снимки стартовых экранов доступны в артефакте `android-apps-and-smoke`. Этот запуск проверяет старт, полный сценарий выше проверяется отдельно.
