# СвойМастер

Сервис поиска частных мастеров для бытовых услуг. Первая версия — учебное приложение с ролями клиента и мастера.

## Команда

Имена и вклад участников пока не определены. Заполним этот раздел после распределения работы.

## Проблема и аудитория

Клиенту нужен мастер для небольшой работы по дому. В приложении можно выбрать услугу, посмотреть описание и цену, затем оставить заявку.

Аудитория — жители города и частные мастера. Для учебного примера выбран Екатеринбург. Это рабочий пример, исследование аудитории пока не проводили.

## Первая версия

- Поиск мастера по имени и услуге, фильтр свободных мастеров.
- Карточка мастера с описанием и фиксированной ценой услуги.
- Заявка с именем, телефоном, адресом, датой и временем.
- Список заявок, отмена и подтверждение выполнения.
- Кабинет мастера с входящими заявками и переключателем доступности.
- Демонстрация проверки через Госуслуги и автоплатежа.

В примере четыре мастера. Кабинет мастера открывается для Алексея, остальные карточки нужны для проверки поиска. Регистрацию других мастеров пока не делали.

## Экраны

| Экран | Назначение |
| --- | --- |
| Выбор роли | Открыть раздел клиента или мастера, сбросить демоданные |
| Поиск мастера | Выбрать услугу, найти мастера, открыть свои заявки |
| Карточка мастера | Посмотреть описание, цену и доступность |
| Новая заявка | Заполнить данные и отправить заявку |
| Мои заявки | Посмотреть заявки клиента |
| Кабинет мастера | Изменить доступность, выполнить демопроверку, открыть входящие |
| Детали заявки | Увидеть ответы и изменить статус согласно роли |

Переходы выполняются кнопками и нажатием на строки списка. Кнопка «Назад» возвращает на предыдущий экран. В деталях заявки есть переход к выбору роли.

## Основной сценарий

1. Клиент выбирает услугу «Сантехника» и Алексея.
2. Заполняет заявку и при желании включает демоавтоплатёж.
3. Заявка получает статус «Новая».
4. Пользователь возвращается к выбору роли и открывает кабинет мастера.
5. Мастер принимает заявку. Статус меняется на «Принята».
6. Мастер нажимает «Работа выполнена». Статус меняется на «Ожидает подтверждения».
7. Клиент открывает ту же заявку и подтверждает выполнение.
8. Статус становится «Завершена». При включённом автоплатеже появляется «Демо: оплачено ... ₽».

Мастер может отклонить новую заявку. Клиент может отменить новую или принятую заявку. За отклонённую или отменённую заявку демооплата не выполняется.

## Ошибки и пустые состояния

Форма проверяет имя, телефон из 11 цифр, адрес и будущее время визита. Если мастер недоступен, создать заявку нельзя. При отсутствии результатов поиска или заявок экран показывает подсказку.

## Технологии и данные

C#, XAML, .NET MAUI 10. Переходы через NavigationPage, логика в code-behind.

Данные мастеров и заявок сохраняются в JSON через Preferences на устройстве. Прототип отдельно сохраняет свои примеры в браузере. Данные прототипа и MAUI-приложения не связаны.

Настоящих аккаунтов и сервера пока нет. Две роли используют общие данные одного устройства. На разных телефонах заявки не синхронизируются.

Целевые платформы: Android, iOS, Windows, macOS. Android APK собраны. Проверка запуска на устройствах и сборка для остальных платформ ещё нужны.

Госуслуги и оплату подключим в дальнейших версиях. Сейчас они работают как демонстрация без настоящего входа и списания денег.
